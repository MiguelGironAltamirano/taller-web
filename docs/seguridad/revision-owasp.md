| A07 | Fallas de identificación y autenticación | Login devuelve siempre `"Credenciales inválidas"` sin importar si el correo no existe, la contraseña es incorrecta o la cuenta está inactiva (no hay enumeración de usuarios). Cambio de contraseña requiere la contraseña actual. | `Login.java`, `AuthExceptionHandler.java` (l. 56–59), `LoginAttemptLimiter.java`, `LoginAttemptLimitTests.java` | Bajo |
| A08 | Fallas de integridad de software y datos | Por acuerdo del equipo, todo cambio entra por PR con el CI en verde (`backend`, `frontend`, `smoke and e2e`) y nada entra directo a `dev` ni a `main`; commits con Conventional Commits. El lockfile se instala con `pnpm install --frozen-lockfile` y el wrapper de Maven fija la versión del build. **No hay** firma de commits ni de releases, ni tags todavía, y las acciones de GitHub se referencian por versión (`@v5`), no por SHA. | `.github/workflows/ci.yml`, `docs/fase-1/04-arquitectura.md`, rama y política de PR documentada en `plan/README.md` | Medio — la regla de PR es un acuerdo del equipo: no se pudo comprobar una protección de rama configurada en GitHub (la API respondió `404`). ## Notas

- **A06 / A08 / A09:** los riesgos residuales medios dependen de pasos fuera del código: el release a `main` (activa Dependabot), la protección de ramas en GitHub y la observabilidad centralizada (Fase IV).
- **A05:** Swagger UI y `/v3/api-docs` son públicos en local y staging (solo describen la API; las operaciones siguen exigiendo JWT) y se desactivan en producción con `APP_API_DOCS_ENABLED=false` (`OpenApiDocsTests`).
- La revisión se realizó con asistencia de IA (Claude Sonnet 4.6 y, en la revisión de la PR #36, Claude Opus 5.5; 2026-11-20). Las afirmaciones de A02, A06 y A08 se corrigieron en esa revisión. Ver `docs/registro-uso-ia.md`.
